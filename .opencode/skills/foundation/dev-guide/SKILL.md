# 开发指南

> 包含开发过程中的疑问确认、记录规范和版本控制

## 1. 开发记录规范

### 1.1 记录格式

#### 时间节点记录
```
## {日期} - {模块/功能}
- {时间点}: {事件描述}
```

#### 疑问确认记录
```
## 疑问确认 - {模块/功能}
| 序号 | 确认时间 | 问题描述 | 确认结果 | 备注 |
|-----|---------|---------|---------|------|
| 1 | YYYY-MM-DD HH:mm | 问题描述 | 确认结果 | 补充说明 |
```

### 1.2 代码生成前必问

| 序号 | 疑问点 | 说明 |
|-----|-------|------|
| 1 | 下级模块 | 是否有更下级组织？层级是否完整？ |
| 2 | Entity类名 | 确认实体类名称是否正确 |
| 3 | 字段命名 | 确认No/Name字段命名 |
| 4 | 包路径 | 确认import路径是否正确 |

### 1.3 使用说明

- 每次生成代码前，先列出疑问清单
- 生成过程中有疑问随时暂停确认
- 生成完成后发送确认给用户

## 2. 版本控制规范

### 2.1 提交消息格式

```
<类型>: <模块名> - <简要描述>
```

| 类型 | 说明 | 示例 |
|------|------|------|
| feat | 新增功能 | feat: 物理建模 - 新增企业模块BZC |
| fix | 修复缺陷 | fix: 人员管理 - 修复删除校验逻辑 |
| docs | 文档变更 | docs: skills - 新增错误处理规范 |
| refactor | 重构代码 | refactor: 工厂模块 - 优化查询逻辑 |

### 2.2 提交粒度

- **一个功能模块一次提交**：不要把多个模块的变更混在一起
- **Domain 和 BZC 分开提交**：先提交 Domain，再提交 BZC
- **skill 文件独立提交**：规范变更单独提交

### 2.3 目录同步规范

- 新增 BZC 目录时，必须在 Domain 下创建对应目录
- 目录结构必须保持一致
